# 同一个内核题，六个模型，编译后真跑

问的是"GLM 写内核是不是有优势"。用口碑答不了这个问题，所以做成实验：
同一道题、同一套命令行、同一台机器的 gcc，评分只看可执行文件的行为。

题目在 `TASK.txt`：用 C99 写一个二维平面应变 Q4 有限元求解器，一个 .c 文件，
`argv` 读 5 个数，stdout 只打印 `tip_uy=<数值>`。

    L=100  H=10  总力 1000 N  端部挠度的梁理论值 17.3333
    (E=210000, nu=0.3, 平面应变 E'=E/(1-nu^2), I=H^3/12)

为什么必须编译后真跑：内核这一类代码的失败几乎全部编译得过、跑得起来、
然后给出一个不像样的数。`0.177` 和 `0.978` 在代码里长得一样长。

## 评分不是"像不像"，是四件事

    compiles    能不能编过
    runs        能不能按约定命令行跑出 tip_uy=
    sane        比值落在 [0.80, 1.05]（梁理论略高估，有限元应该略低）
    converges   10x2 -> 20x4 -> 40x8 时比值单调靠近 1

参考答案没给模型 —— 给了就能把常数写死。

## 结果（每格 3 次独立生成，temperature 0.3）

`reasoning_effort: low`，max_tokens 20000：

    模型                  编译   算出对的值      端部比值           生成耗时
    DeepSeek-V4.1-Flash   3/3    3/3            0.9779 三次全部     35-103 s
    DeepSeek-V4-Pro       3/3    3/3            0.9779 三次全部     111-157 s
    Kimi-K2.7-Code        3/3    3/3            0.9779 / 0.9757 / 0.9779  161-264 s
    Qwen3.7-Max           3/3    3/3            0.9779 三次全部     70-103 s
    GLM-5.3               3/3    2/3            0.9779 / 0.9779 / 1.3e-08  114-132 s
    GLM-5.3-Flash         3/3    0/3            0.2445 / 无输出 / 0.0611   29-33 s

"0.9779"这个数在四个模型、九次生成里逐位一致，这不是巧合：正确实现必然
收敛到同一个值。它同时也是这个题库的自检 —— 如果某个模型的答案落在
0.9757（Kimi r2），那是它自己的离散细节不同，仍在容差内。

## GLM 到底错在哪：同一个地方，三次

GLM 三次失败全在 Q4 的形函数导数，而且错法一模一样 —— 漏了 1/4：

    dN/dxi  = -0.5*(1-eta)     错（GLM-5.3-Flash r1）
    dN/dxi  = -0.25*(1-eta)    对

后果是可预测的：多一个 2，B 矩阵大 2 倍，K 大 4 倍，位移小 4 倍。
实测 0.1774 / 0.7095 = 0.25，正好。GLM-5.3-Flash r3 那版是 0.0611，
0.9779/16 —— dN 大了 4 倍、刚度大了 16 倍，同一个错法错得更彻底。

把我自己改一个字（4 处 0.5 -> 0.25）之后，那个文件立刻给出 0.9779。
所以它不是"大体上对"，它是差一步，而差的那一步在代码里看不出长短。

GLM-5.3 的 r3 是另一种：位移几乎为 0（1.3e-08）。它不是写错公式，是
装出来的系统在数值上退化了 —— 一样编译过、一样跑得动、一样打印出
一个 tip_uy=。

## 单点探针：同一件事在 8 行里复现

完整题目太贵，不容易重复。所以另有一个只问那 8 个表达式的探针
（`micro_dN2.json`，每个模型 4 次）：

    模型                  答对
    DeepSeek-V4.1-Flash   4/4
    Kimi-K2.7-Code        4/4
    Qwen3.7-Max           4/4
    GLM-5.3               4/4
    GLM-5.3-Flash         3/4（错的那次相对误差 1.0，即整体差一倍）
    DeepSeek-V4-Pro       2/4（另 2 次干脆没输出 JSON —— 是格式问题，不是算错）

结论要连着两句读：GLM-5.3 在被直接问公式时能答对 4/4，但在必须自己
组织成 165 行代码时，三次里错了一次、且错的方式固定。**知识的缺口不在
"知不知道"，在"写的时候会不会漏"。** 这也说明单点问答测不出内核能力。

## 第一个坑是我自己的

第一次跑，GLM-5.3 和 DeepSeek-V4-Pro 都"编译失败"。看结果才发现
`content_chars: 0`、`reasoning_chars: 64192`、`finish_reason: length` ——
8000 token 的预算被推理内容烧光，正文一个字没有，编译的是空文件。
那不是模型的失败，是我给错了预算。`reasoning_effort: low` 能关掉思考，
之后两家都正常出代码。这一条留在这里，因为它是最容易读反的一张图。

## 一句话结论

在写求解器内核这件事上，GLM 没有优势。它能写对（GLM-5.3 r1/r2 与其余
四个模型逐位同值），但它的失败率明显更高，而且失败集中在同一个算子上；
反而它比别的模型更省 token、更快（2.5k token vs 7k-11k），像是"想得少
所以也漏得多"。这个判断只覆盖这一道题、六次生成，不覆盖"GLM 写内核不行"。
